# Player stats and projection options

Researched 25 September 2026. The current roster uses imported Yahoo player IDs. The UI's numbers are deterministic **demo projections**, not a provider feed, and matchup opponents are a fabricated nine-week round robin.

| Source                                                                  | Useful data                                                                                               | Fit and constraints                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [FantasyPros API](https://www.fantasypros.com/api-data/)                | Weekly and rest-of-season projections, player points, player metadata and external IDs                    | Best first candidate for this league's projection display. A free key is for prototyping; personal production access requires HOF, while a commercial or redistributed app needs a commercial agreement. [Access terms](https://support.fantasypros.com/hc/en-us/articles/49749297704475-How-do-I-request-access-to-the-FantasyPros-API). |
| [SportsDataIO NFL](https://sportsdata.io/developers/workflow-guide/nfl) | Player game stats, weekly projections, fantasy points for several scoring systems, injuries and schedules | Strong paid option for integrated live scoring and projections. Weekly projections update during the week. Confirm licensing, cost and whether its Yahoo scoring preset matches this league's settings.                                                                                                                                   |
| [nflverse](https://github.com/nflverse/nflverse-data)                   | Open downloadable weekly player stats, rosters and play-by-play                                           | Good historical and completed-game stats source, with attribution and license review. It does not provide a ready weekly projection product, so projections would need a separate model or provider. [Player stats access](https://github.com/nflverse/nflreadr).                                                                         |
| [Sleeper public API](https://docs.sleeper.com/)                         | Player directory, league and matchup data                                                                 | Useful for player identity crosswalks and comparison. Its published API docs do not establish a supported projection feed, so do not depend on undocumented endpoints for this feature.                                                                                                                                                   |
| [Yahoo Fantasy Sports API](https://developer.yahoo.com/api/)            | Yahoo league, team and player data                                                                        | Worth evaluating if Yahoo sync becomes a goal because the imported IDs already come from Yahoo. Requires an authorized Yahoo account and OAuth. Verify projection field coverage and usage rights before selecting it as the projection source.                                                                                           |

## Recommended integration path

1. Choose the scoring rules first, including passing, yardage, reception, kicker and defense values. “Full PPR” alone is insufficient to calculate reliable fantasy points.
2. Trial FantasyPros projections and its external ID map against all 158 imported Yahoo IDs. Keep a reviewed mapping for unmatched players and team defenses.
3. Fetch provider data on the server, cache by season/week and timestamp, and expose only normalized `projectedPoints`, `source` and `updatedAt` to the browser. Keep the API key on the server.
4. Show a missing value when a player cannot be matched. Remove the demo estimator once real data is connected. Use the same normalized points for roster and matchup totals.
